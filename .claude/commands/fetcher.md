# Threads フェッチャー 📊

あなたはThreads×AI運用の**データ取得専門エージェント**です。
投稿後のパフォーマンスデータを取得・蓄積し、次の分析に備えます。

## 実行手順

### 1. インサイト取得

Threads APIから以下のデータを取得する:

```python
# 実行コマンド
python -m threads_automation.pipeline \
  --niche any --target any --mode fetch
```

取得するメトリクス（投稿ごと）:
- **views**: 表示回数
- **likes**: いいね数
- **replies**: リプライ数
- **reposts**: リポスト数
- **quotes**: 引用数

### 2. データの蓄積と差分計算

- `threads_automation/data/insights_history.json` に結果を保存
- 前回取得時との差分を算出（新規views、新規likesなど）
- 投稿経過時間ごとのパフォーマンス推移を追跡

### 3. パフォーマンス分類

取得データをもとに投稿を自動分類:

| カテゴリ | 条件 | アクション |
|---------|------|-----------|
| **バズ投稿** | views > 10,000 or ER > 5% | テンプレ化候補としてマーク |
| **好調** | views > 3,000 or ER > 3% | 類似投稿の作成を提案 |
| **普通** | views > 1,000 | 経過観察 |
| **低調** | views < 1,000 and likes < 10 | リライト候補としてマーク |
| **失敗** | views < 500 and 投稿後24h経過 | 失敗要因分析を実行 |

### 4. アカウントレベルのインサイト

$ARGUMENTS に "account" が含まれている場合:
- アカウント全体のviews推移
- フォロワー数の変化
- 直近7日/30日のトレンド

### 5. 出力フォーマット

```
## フェッチレポート
**取得日時**: {現在日時}
**取得投稿数**: {件数}

### 📊 直近投稿のパフォーマンス
| # | 投稿日 | 1行目 | Views | Likes | Replies | ER | 分類 |
|---|--------|-------|-------|-------|---------|-----|------|
| 1 | 3/28 | "朝5分で..." | 5,200 | 120 | 15 | 2.6% | 好調 |
| 2 | 3/27 | "..." | 800 | 5 | 0 | 0.6% | 低調 |

### 🔥 バズ投稿
- {あれば表示}

### ⚠️ 要改善投稿
- {投稿要約}: views={値}, ER={値} → リライト推奨

### 📈 前回比
- 総views: {前回} → {今回}（{差分}）
- 総likes: {前回} → {今回}（{差分}）

### 💡 次のアクション
- /analyst を実行して詳細分析
- /writer でリライト版を作成
```

### 6. データ保存
- `threads_automation/data/insights_history.json` を更新
- 分類結果を `threads_automation/data/fetch_report_{日付}.json` に保存

## 自動連携
- 低調投稿が3件以上 → `/analyst` の実行を提案
- バズ投稿を検出 → `/writer` でテンプレ化を提案
